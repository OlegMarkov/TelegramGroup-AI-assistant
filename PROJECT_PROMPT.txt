## WHAT THIS IS

A production Telegram bot (Node.js, CommonJS) that summarizes group chats and
public Telegram channels with DeepSeek, lets users search their message history,
highlights topics/keywords they care about, and sells premium subscriptions paid
in Telegram Stars (currency XTR — no external payment provider).

Repo: C:\Projects\Telegram AI assistant   (git, branch `main`)
Deployed: Linux VPS via docker compose (bot + Redis). See DEPLOY.md.
Languages: English + Russian, full parity enforced by tests.
Status as of this writing: feature-complete v1, 180 tests passing, live.

8.  Filters: category matching by bilingual topic VOCABULARY (not by the

    keywords with stem matching, then keyword gating (1 free / 20 premium).
9.  Channels: follow public channels, read via https://t.me/s/<handle> web
    preview, summarize them; button-driven management; 1 free / 20 premium.
10. Payments hardening: pre_checkout declines duplicate purchases; a payment
    that lands anyway EXTENDS rather than replaces the active period.
11. Pricing raised to 300 stars/month, 3000/year (before any paying customers).
12. DeepSeek tuning: reasoning turned OFF (`thinking: {type:'disabled'}`),
    max_tokens 3000, timeout 120s, explicit output format (3-5 **headers**,
    <=12 bullets), CommonMark ** -> Telegram legacy * normalization.
13. /help — the full guide, every number interpolated from the limit constants.

## LOAD-BEARING DESIGN DECISIONS (do not "simplify" these away)

* Free limits are ALLOWANCES, NOT booleans. Free = 1 group, 1 channel,
  1 keyword. So `maxChannels === 0` is NOT a premium test — access is decided
  per item by isChannelWithinLimit / allowedKeywords, "earliest N wins", so a
  lapsed subscriber keeps their oldest item instead of losing all 20.
* Keyword gating is enforced in digest.js (on the way OUT), not on the /filter
  screen (on the way IN) — a subscription can lapse in between.
* Ingestion tracks EVERY member of EVERY group regardless of plan; the limit
  only caps which chats a given user may personally query.
* Channel posts are fetched at request time and NEVER written to the DB. Only
  the generated summary is cached. That is why /find covers groups only.
* Channel IDs are synthetic positive ints from CHANNEL_ID_BASE = 1e12; real
  Telegram group/channel ids are always negative. Disjoint by construction — a
  collision would serve one chat's content to another chat's members.
* Channel handles are validated by an anchored regex BEFORE any fetch, and
  redirects are not followed (maxRedirects: 0). That is both the SSRF control
  and how a private/nonexistent channel is detected (Telegram answers 302).
* digest_cache is keyed by (chat_id, hours, LANGUAGE) and fingerprinted by
  "maxMessageId:count" — no TTL; it invalidates the instant the window changes.
* getActiveSubscription orders by LONGEST remaining, not most recent, so a
  cheap plan can never shorten an expensive one.
* Model output goes through normalizeModelMarkdown(); quoted user/channel text
  goes through escapeMarkdown(). Never mix the two up.
* Every Markdown send of model output has a plain-text retry — unbalanced * or
  _ from an untrusted source otherwise makes Telegram reject the whole message.
* Third-party text is fenced in <content>...</content> in the DeepSeek prompt
  and the fence tokens are stripped from the payload — prompt-injection control.
* Reply-keyboard taps arrive as plain text; isMenuButtonText() keeps them out
  of ingested conversation and out of captureReply prompts, IN EVERY LANGUAGE
  (a user who switched language still has the old keyboard client-side).
* .gitattributes forces LF — CRLF breaks multi-line `run: |` on CI's Linux box.
* /stats is deliberately absent from the published command menu and replies
  with NOTHING to non-admins, so its existence isn't discoverable.

  on Node < 24.


## FIXED 2026-09-05 (regression tests exist — do not reintroduce)

* getRecentMessages() took the OLDEST N in the window, so a busy group's
  summary silently omitted the most recent activity AND froze the digest cache
  (the fingerprint keys on the highest message id, which never changed). Now a
  DESC-limited subquery re-sorted ascending.
* The "earliest N wins" allowance subqueries did not filter is_active, so a
  dead group kept its slot and a free user whose oldest group lost the bot
  could summarize nothing at all.
* /find rendered chat title, author and message body as Markdown unescaped and
  with no plain-text retry. Now escaped like the digest highlights, retried
  plain, and split with splitForTelegram (escaping can nearly double length).
* subscriptions.telegram_charge_id is now a partial UNIQUE index and
  createSubscription() deduplicates on it; handleSuccessfulPayment() returns
  the stored receipt on a redelivery instead of granting a second period.
* getDueScheduledDigests() now reads last_sent_at, so a retried BullMQ tick
  cannot re-send a digest already delivered that hour.
* The rate-limit refusal is localized (it runs before auth(), so it reads the
  stored language only on the rejection path), and its map is swept.
* Retention no longer rides the Redis-backed tick. startRetentionSweeps() runs
  it on an unref'd hourly setInterval plus once at boot; the tick still calls it
  behind a 5-minute gap guard. The last successful sweep is persisted in the new
  app_state table, shown in /stats, and warned about after 24h.
* PRIVACY.md and the /privacy copy now name DeepSeek and say it processes in
  China, state exactly what is sent (sender name + first 300 chars per group
  message, 600 per channel post, no identifiers) and what never is (/find never
  leaves the server), and describe the summary cache's lifetime. The 300 comes
  from digest.js's exported GROUP_MESSAGE_CHARS, not from the copy.
* Digest sends are paced (20/sec) through utils/telegramSend.js, wait out a
  429 for its stated retry_after, and retry a transient failure a bounded
  number of times. A 403 disables that user's scheduled digest with
  disabled_reason='blocked' rather than retrying daily for ever; a 429 or a
  network error must never take that path. markDigestSent now runs only after
  a send genuinely succeeded. The Markdown->plain fallback is narrowed to a
  400, the only code that means "I could not parse that".
* /status reports plan, expiry, summaries used today and every allowance with
  its locked overflow. renderLimit() turns PREMIUM_LIMITS' real Infinity into
  a word. Its Subscribe button and the reminder's Renew button are one
  registration (renew:open) in subscribe.js, reusing the real handler.
* Expiry reminders at 3 days, 1 day and on lapse ride the same hourly tick.
  Recorded per (subscription, stage) in subscription_reminders, so a retry
  cannot re-notify and each new period gets its own set. Stage windows are
  half-open and the lapse stage is bounded at BOTH ends, or a first deploy
  would DM everyone who ever lapsed. A 403 marks the stage done; a transient
  failure leaves it retryable.
* /refund, /grant, /revoke are admin-only, silent to non-admins, and absent
  from PUBLIC_COMMANDS. A refund only marks the row once Telegram accepted it.
  /grant writes telegram_charge_id NULL — a placeholder is what broke the
  index. Comps use plan 'comp', which is deliberately NOT in
  SUBSCRIPTION_PLANS, because pre-checkout validates purchases against that map.
* Late joiners are reached two ways: the notice is re-posted on
  new_chat_members (claimJoinNotice throttles it to once per 24h per chat, and
  the claim IS the check so a burst of joins cannot each decide it is due), and
  every GROUP summary carries a footer naming the bot and linking /privacy.
  A DM per new member is impossible - Telegram will not let a bot message a
  stranger.
* Group admins get /pause and /resume, gated on getChatMember and failing
  CLOSED - a completely different notion of "admin" from config.adminUserIds.
  Members get a per-user opt-out from /privacy that applies in EVERY chat and is
  offered again after /forgetme. Both are checked in ingestionPolicy.js before
  saveMessage; the chat link is still kept, because being unrecorded is not the
  same as being unable to use the bot. A paused chat refuses /summary rather
  than summarizing what is still stored.
* Users can store a fixed UTC offset (users.tz_offset_minutes, minutes because
  of :30 zones). utils/timezone.js enumerates FROM hour_utc and labels each
  option with the local time it lands on, so half-hour offsets are exact rather
  than rounded into a promise the hourly tick cannot keep. The scheduler is
  untouched: hour_utc is still the stored value and the only thing the tick
  matches. NULL offset = never asked = the original four UTC hours. Fixed
  offsets, not IANA zones - the DST reasoning is in a comment at the top of
  that file and is the decision to revisit, not the code.
* Photo/video/document CAPTIONS are ingested as text, flagged with
  messages.is_caption, and rendered in the AI transcript with a "[media] "
  prefix so the model reads them as describing an image. The flag is a column
  rather than baked into the text, so the marker never reaches /find results or
  filter highlights. Media with no caption stays unstored. PRIVACY.md and the
  /privacy copy were updated in the same change - this increases what is
  retained, so the "non-text content is ignored entirely" line was false.
* Comped subscription rows carrying a hand-typed placeholder charge id are
  nulled at startup by nullPlaceholderChargeIds() before ensureChargeIdIndex()
  runs, so idx_subscriptions_charge_id finally gets created. stars_paid = 0 is
  the signal: a row where no stars moved cannot be a real Telegram charge.

## KNOWN OPEN ISSUES (verified 2026-09-05, not yet fixed)

1. EDITED messages are not ingested — an edit is a separate update type and
   nothing handles it, so the stored copy keeps the original wording.
   (Captions ARE ingested as of 2026-09-05.)
2. /find uses LIKE '%q%' with no FTS index and no escaping of % / _ (the
   escaping IS done as of 2026-09-05; the FTS index is not).
3. getRecentMessages caps at 200 messages with no note to the user when a
   busier window is truncated.


## ENVIRONMENT / OPS QUICK REFERENCE

.env keys: BOT_TOKEN, DEEPSEEK_API_KEY, DEEPSEEK_MODEL (deepseek-v4-flash),
DEEPSEEK_TIMEOUT_MS, REDIS_*, DATABASE_PATH, ADMIN_USER_IDS,
MESSAGE_RETENTION_DAYS (90), PURGE_AFTER_REMOVAL_DAYS (7), LOG_LEVEL.

BotFather setup: /setprivacy -> DISABLE (required, or the bot cannot see group
messages at all).

Redis must be up for scheduled digests. Retention enforcement does NOT need it:
it runs on its own hourly interval in the bot process, and the last successful
sweep is reported in /stats. On-demand /summary and /find work without Redis.

Backup: docker compose exec bot node -e "...VACUUM INTO..." — a plain file copy
can miss data in bot.db-wal.

Deploy update: git pull && docker compose up -d --build (migrations run at
startup, SIGTERM is handled cleanly).
